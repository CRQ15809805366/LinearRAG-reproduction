# Repository instructions

- Keep the four main concerns separate: core Python code in `src/`, runtime inputs and outputs in `data/`, internal records in `project/`, and externally readable research material in `research_report/`. Keep bounded experiment adapters and usage notes in `experiments/`; they configure studies around `src/` and write generated evidence under `data/output/`.
- Start with `project/agent/experiments/README.md` for current Q1-Q8 status and evidence paths.
- Treat the reproduced LinearRAG implementation as an experimental object. Do not refactor algorithms or change behavior unless the task explicitly requires it.
- Run the minimal smoke test with `python -m src.smoke_test`; do not present it as the full `src.run` experiment.
- Keep the default BFS retrieval path distinct from the optional `--use-vectorized-retrieval` path.
- Resolve project-owned runtime paths through `src.paths`, not through the caller's current working directory.
- Do not commit local models, datasets, caches, generated run results, secrets, or virtual environments.
- Treat `project/human/` as the user's private learning, planning, and interpretation space. Do not treat drafts there as externally validated research claims.
- Treat `project/agent/` as agent-owned operational and research memory. Use it to record each major version's decisions, experiment designs and indexes, verified state, risky or consequential operations, recovery information, and other curated evidence worth preserving. Do not store bulk machine-generated logs, predictions, caches, or run outputs there; those belong under `data/output/`. Do not create records for trivial work merely for completeness.
- Treat `research_report/` as the externally readable research layer for reports, curated tables and figures, and presentation material. Every quantitative claim there must be traceable through `project/agent/` to raw evidence under `data/output/`; do not select or rewrite results merely to improve presentation.
- Write all Agent-maintained files under `project/agent/` in English. Preserve commands, paths, identifiers, and raw evidence in their original form when translation would reduce fidelity.
- Before version work or debugging runtime, environment, cache, or reproduction issues, inspect the relevant records in `project/agent/` (starting with `BASELINE.md` when applicable and `experiments/README.md` for formal evaluations). Update or add a record when the work changes a recorded fact or leaves important evidence for a later agent. Treat recorded environment and runtime facts as snapshots and re-verify anything that may have drifted.
- The verified local OpenAI-compatible model is `qwen3.8-flash`. Since 2026-09-22, `src.utils` reads `OPENAI_API_KEY` and `OPENAI_BASE_URL` directly from the untracked project-root `.env.local` and passes them to the OpenAI client without injecting them into the process environment; the Windows user-level copies were removed so they no longer override CC Switch globally. Never commit, display, or copy the contents of `.env.local`; do not ask the user to re-enter the values unless that file is also absent or a live call proves them invalid. This endpoint is suitable for local bounded runs, but it is not the paper's `gpt-4o-mini`; always record which model produced an experiment result.
- `origin` currently points to the upstream authors' repository (`DEEP-PolyU/LinearRAG`). Never push to it. Configure and verify a user-owned remote before any push.
