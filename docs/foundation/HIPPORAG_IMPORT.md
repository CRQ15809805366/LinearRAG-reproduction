# HippoRAG 引入基线

本文记录首次引入时的来源、执行边界和兼容决策，允许修订；后续集成变化与实验结果记录在相关实验记录中。

## 来源与执行边界

- 官方仓库：`https://github.com/OSU-NLP-Group/HippoRAG.git`。
- 外部源码版本：标签 `v1.0.0`，固定提交 `b144c46df14cabe5f5822d8caded4bec5f709461`。
- 本地改动：保留兼容补丁；该实现不是未经修改的官方源码，也不是 HippoRAG2。
- 使用独立解释器和保留的依赖快照隔离外部环境。

适配器通过 JSON 与外部驱动交换数据，返回本项目的段落结构。只有子进程导入官方模块，父进程的导入路径不包含这些模块。运行位置相对于项目根目录解析。

本地配置使用 `qwen3.8-flash`、本地 `all-mpnet-base-v2` 及官方 HuggingFace 均值池化、显式 OpenIE 关系、同义候选搜索与 PPR（`damping=0.5`、相似度阈值 `0.8`、`doc_ensemble=False`、`dpr_only=False`）。这没有复现论文的 GPT/Contriever/ColBERT 配置。编码使用 CUDA PyTorch，近邻搜索使用 CPU FAISS。

## 关键兼容决策

- 仅在选择 ColBERT 路径时导入 ColBERT。
- 保留支持 CPU 的 FAISS 精确内积搜索。索引分区数和近邻数受实体数限制，避免小语料出现无效填充候选。
- 段落 NER 失败时抛出错误，不沿用上游的无限重试循环。驱动持久化已完成的段落抽取和问题 NER，以便续跑。
- 调用官方 `create_graph` 和 `RetrievalModule`，只计算该路径需要的 `kb_to_kb` KNN。保留官方提示词和排序。
- 桥接层读取项目本地凭据文件，直接向客户端传递凭据。审查时的源码确认：`max_retries=0`、超时 180 秒、`httpx.Client(trust_env=True)`；子进程继承系统代理设置。兼容补丁为桥接层的 `qwen3.8-flash` OpenIE 客户端启用 JSON 模式，并将输出上限提高到 16384 tokens。
- Windows 子进程使用 `KMP_DUPLICATE_LIB_OK=TRUE` 和 `OMP_NUM_THREADS=1`，规避 PyTorch/FAISS 的 OpenMP 冲突。

## 集成边界

共享缓存将语料抽取、图状态和排序结果与实验答案、评价分离。索引身份包含驱动的 SHA-256，因此驱动变化会使缓存无法复用。外部源码、依赖变化以及同一路径下模型内容的变化没有完整指纹；遇到这些变化应选择新的 `cache_dir`。不支持并发写入缓存。

共享排序结果不包含标准答案和生成答案；标准答案仅在返回时附加。段落抽取和问题 NER 在缓存未命中时会调用付费 API，包括只执行检索的调用。其用量统计不含答案生成和评价；缓存总量代表获取成本，单次运行增量代表新增用量。

共享缓存分离之前写出的请求与封板时的协议不兼容。一次调用失败、尚未写出运行摘要时，成功响应的用量可能已经保存在缓存日志中；该用量不构成完整的服务商账单。

`HippoRAG.index()` 仅保存语料；实际抽取、图准备和检索在子进程中执行。恢复抽取或图产物属于恢复过程，不是冷索引。
