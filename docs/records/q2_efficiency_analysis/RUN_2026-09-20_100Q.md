# Q2 有界正式效率结果：100 题

## 状态

于 2026-09-20 完成。

原始证据：`data/output/q2_efficiency_analysis/q2-formal-100q-20260920/`

## 实际协议

- 数据集：完整的 658 段 2WikiMultiHopQA 语料。
- 问题：按固定种子抽取 100 题。
- 嵌入模型：本地 `all-mpnet-base-v2`，使用 CUDA；NER：`en_core_web_trf`。
- 检索：官方 BFS 路径，Top-5。
- 参数：`max_iterations=3`、`passage_ratio=0.05`、`iteration_threshold=0.4` 和 `top_k_sentence=1`。
- 一次不计时预热，随后五次计时检索。
- 复用第一阶段成功冷索引的完整缓存，未再创建第二个冷索引。
- 测得的 2.417 秒属于缓存恢复和图重建，不是冷索引耗时。
- 在独立空缓存中完成三次独立冷索引观测。首次为 `q2-design-check-20260920`；另外两次为 `q2-cold-index-repeat-2-20260920` 和 `q2-cold-index-repeat-3-20260920`。
- `NoLLM` 动态拒绝任何生成模型调用。

## 解释

实际证据显示，前四次本地检索延迟稳定，第五次较慢。中位数接近第一阶段 10 题的 0.152212 秒/题，因此增加到 100 题没有实质改变观察到的每题延迟。

论文在不同硬件上报告索引 249.78 秒、检索 0.093 秒/题。本地中位数分别约为这两个值的 2.45 和 1.66 倍。由于硬件与详细运行环境不一致，这些差异只是描述性比较，不能证明实现缺陷。

本次仅建立本地 LinearRAG 结果，没有执行 GraphRAG 基线，因此没有复现论文的方法间效率排名。
